# Инструкции для нейросетевых агентов — Optima

Читайте этот файл до изменений проекта и сервера. Подробная карта: docs/AI_OPERATIONS.md.

## WEB proxy — НЕ ТРОГАТЬ

Без отдельного прямого запроса владельца не изменять, не останавливать, не перезапускать, не переустанавливать и не удалять Telegram WEB proxy. Задачи сайта, авторизации, карты, закупок и деплоя не дают разрешения менять прокси.

Защищённые объекты сервера:
- /opt/telegram-webproxy/** и telegram-webproxy.service;
- /etc/systemd/system/telegram-webproxy.service;
- /etc/nginx/conf.d/telegram-webproxy.conf;
- /etc/nginx/snippets/telegram-webproxy.conf;
- включение этого snippet и маршрут /telegram/web/ в Nginx;
- loopback-порты 19590, 19591, 19592, секреты подключения, прямой выход с VPS.

Не заменять конфигурацию Nginx целиком шаблоном из deploy: действующий файл содержит совместные настройки сайта и прокси. Не менять firewall, TLS, DNS и общие порты так, чтобы нарушить прокси. Обычную необходимую перезагрузку Nginx для сайта выполнять только после nginx -t и проверки сохранности маршрута прокси. Не читать и не выводить секреты прокси для работы над сайтом.

## Работа над сайтом

- Сохранять исходный дизайн Optima 0.23.0; не создавать заменяющий кабинет.
- Регистрация: email, пароль (от 6 символов) и код; вход: email и пароль подтверждённого аккаунта (прямое решение владельца от 29.10.2026). Компания создаётся только после подтверждения кода. Не обходить подтверждение регистрации через публичное демо.
- Состояние кабинета и данные района сохраняются через API. Изоляция по владельцу обязательна; синтетические компании не являются реальными клиентами.
- Новая компания начинает с пустого кабинета: не создавать за пользователя закупки, потребности, задачи, товары, сообщения и адреса. Старые шаблоны очищать только по точному совпадению, сохраняя пользовательские правки и проверку revision.
- Не придумывать название компании и ИНН. Каталог содержит только опубликованные предложения; шаблонные товары не выдавать за доступные. Сравнение цен показывать только при известном источнике исходной цены и не называть его фактической экономией.
- Для текущего этапа в меню покупателя пять разделов: обзор, закупки, потребности, сообщения, документы. Карту, аналитику и внутренние задачи не возвращать в основную навигацию без запроса. Подпись «ВТБ Бизнес Платформа» убрана по запросу владельца.
- Настройки компании открываются через профиль и нижний пункт меню. Реквизиты и контакты сохраняются в Company через owner-only API с profile_revision; не складывать контакты в общий каталог или локальное состояние закупки. Почта для связи не меняет почту входа. Реквизиты оформленных закупок защищены от изменения.
- Одна почта может владеть двумя независимыми бизнес-профилями: покупатель и поставщик. BusinessProfile связывает пользователя с отдельной Company; реквизиты и состояние кабинета не копировать. X-Company-Profile проверяется по владельцу на каждом запросе; User.company_id не менять при переключении. Новую компанию создавать только по явному выбору пользователя. Перед переключением завершить сохранение старого кабинета.
- Светлая и тёмная темы переключаются независимо от бизнес-профиля; предпочтение хранится локально. Не инвертировать изображения фильтрами.
- Комиссия: 3% положительной экономии. Реальных платежей и электронной подписи нет; документы демонстрационные.
- Не раскрывать .env, почтовые коды, API-ключи, пароли, сессии и connection.txt в логах, фронтенде, ответах или архиве.
- Сохранять БД, volumes, OTP_SECRET и действующие сессии при обычном обновлении. Не выполнять down -v, сброс БД, повторный seed с удалением или замену секретов без соответствующего запроса.
- До правок читать текущие файлы: имена релизов и результаты старых проверок могут устаревать.
- Проверять изменения соразмерно риску. Для комментариев достаточно проверки синтаксиса и отсутствия изменения исполняемого содержимого.
- После изменения frontend/product запускать node frontend/build.cjs; не редактировать собранные assets или vendor вручную.
- Архив собирается python -m scripts.package_release; новые инструкции должны попасть в архив.
