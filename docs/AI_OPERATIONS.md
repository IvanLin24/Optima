# Карта проекта для нейросетевого агента

Основные правила — ../AGENTS.md. WEB proxy НЕ ТРОГАТЬ без отдельного прямого запроса владельца.

## Где искать код

- app/main.py: FastAPI и подключение маршрутов.
- app/auth.py, app/mail.py, app/config.py: одноразовые коды, отправка почты, настройки. Коды не логировать; секреты не подменять.
- app/prototype.py: серверное состояние исходного дизайн-прототипа; revision защищает от перезаписи.
- app/scene.py: личный мир района, предприятия, операции, потребности и закупки. Все запросы ограничены owner_company_id.
- app/models.py, migrations/: схема БД; изменения оформлять миграциями, существующие данные сохранять.
- frontend/product/: исходный интерфейс, prototype-session — вход и сохранение; district — карта. frontend/vendor — сторонние библиотеки.
- frontend/build.cjs: сборка исходников в хешированные assets и index.html.
- docs/API.md и docs/openapi.json: контракт API для фронтенда.
- tests/: проверки авторизации, изоляции, расчётов и переходов состояния.
- scripts/package_release.py: allowlist исходников; var, dist, .env, БД и письма не публикуются.

## Сервер

Сайт: https://optima.casa/, VPS 45.148.116.102, Ubuntu 22.04. Пути стабильные; текущую цель symlink проверять перед работой:

- /opt/procurement/current — активный релиз;
- /var/www/optima/current — статический фронт;
- /etc/procurement/backend.env — приватные настройки, не печатать;
- Docker Compose project procurement, API 127.0.0.1:8000, PostgreSQL без публичного порта;
- /etc/nginx/sites-available/optima-domain и procurement — действующие сайты;
- /var/backups/procurement — приватные резервные копии;
- procurement-expiry, procurement-backup, procurement-certificate — обслуживание сайта.

## Отдельный защищённый сервис

Telegram WEB proxy расположен в /opt/telegram-webproxy и управляется telegram-webproxy.service. Nginx передаёт /telegram/web/ в локальный WEB listener 19590; служебные порты 19591–19592 не открывать наружу. Выход напрямую с VPS. Не задавать VPN/SOCKS5, не менять секреты, лимиты, бинарник или маршруты при работах над сайтом. Файл connection.txt приватный, не включать в архив и не публиковать.

Перед деплоем сайта сохранить действующие конфигурации и БД. Изменять только нужные фрагменты, сохраняя include прокси. Проверить nginx -t, здоровье API и работоспособность страницы. Прокси не перезапускать ради обновления сайта. Если задача требует затронуть защищённый сервис, нужен прямой запрос владельца именно на это изменение.

## Границы демо

Тверской район: географическая граница реальная, предприятия и платежи синтетические. Данные разных аккаунтов изолированы логически в одной PostgreSQL, а не отдельными физическими серверами. Слово «смарт-контракт» здесь означает программный контроль условий и состояний; блокчейна и юридической электронной подписи нет. Не выдавать демо-подтверждения за реальную подпись или списание денег.
