# Контракт для подключения бэкенда

Версия 0.1. Все данные прототипа вымышлены. Интерфейс работает автономно, реальные запросы в ВТБ не выполняются.

Сейчас `dist/js/data.js` содержит предложения, `domain.js` расчёты, `store.js` локальное состояние. Эти три границы позволяют заменить тестовые данные ответами сервера без изменения дизайна.

## Предложение

`id`, `sku`, `name`, `spec`, `unit`, `category`, `quantity`, `step`, `price` (текущая цена клиента), `groupPrice`, `delivery`, `groupDelivery`, `otherQuantity`, `threshold`, `participants`, `supplier`, `deadline`, `deliveryDate`.

Все суммы в рублях, включая НДС по единым условиям сравнения. В промышленном API хранить деньги в копейках целыми числами, отдельно передавать налоговые условия. Цена группы должна быть подтверждена поставщиком для нескольких независимых юридических лиц.

## Потребность

`id`, `name`, `spec`, `quantity`, `unit`, `price`, `deadline`, `source`. Сопоставление требует совпадения спецификации и единицы и совместимого срока. Суммы платежей сами по себе не определяют SKU.

## Предлагаемые endpoint-ы

| Запрос | Результат |
|---|---|
| GET /api/v1/offers | Подборка предложений и фильтры |
| GET /api/v1/offers/:id | Подробные условия, версия, состав группы без персональных данных |
| POST /api/v1/quotes | Индивидуальный расчёт для offerId, quantity, needId |
| POST /api/v1/needs | Создание/валидация потребности |
| POST /api/v1/needs/import | Загрузка документов после согласования режима обработки |
| GET /api/v1/orders | Заявки текущей компании |
| POST /api/v1/orders | Подтверждение quoteId, termsVersion, согласия |
| POST /api/v1/orders/:id/cancel | Отказ согласно правилам закупки |
| GET /api/v1/events | Журнал статусов |

В запросах на подтверждение нужна идемпотентность (Idempotency-Key). Сервер повторно проверяет цену, объём, версию, срок и права. Интерфейс не является источником истины для цены и состояния. Ошибка 409 означает изменение условий: показать обновлённый расчёт и запросить новое согласие. Не принимать пользовательскую стоимость из localStorage как договорную.

## Состояния

`collecting` (сбор группы), `ready` (объём набран), `requote` (нужно новое согласие), `supplier_confirmed`, `cancelled`, `expired`. Текущий фронтенд реализует collecting, ready и cancelled. Ready означает только набор объёма, а не подтверждение оплаты или поставки.

## Что ещё не подключено

Банковские API, счета клиентов, ЭП, ЭДО, платежи, OCR PDF/фото, блокчейн. Логика подтверждения в прототипе моделирует правила групповой закупки и не является развёрнутым смарт-контрактом.
