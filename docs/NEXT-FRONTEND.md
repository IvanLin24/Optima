# Optima / Next — самостоятельный frontend

**Это новая реализация интерфейса совместных закупок, без использования компонентов, CSS или шаблонов предыдущих Optima/Optima V2.** Вместо кабинета с сеткой метрик начальной точкой является конкретная закупка: товар, реальные характеристики, поставщик, порог партии, количество, расчёт и самостоятельное оформление участия.

## Запуск на Windows

Распакуйте архив целиком, затем запустите `START_WINDOWS.bat`. Требуется Python 3, внешние Python-библиотеки не нужны. Программа откроет:

`http://127.0.0.1:4181/next/`

Если порт 4181 занят, launcher выберет следующий свободный из диапазона 4181–4190.

## Запуск внутри Optima-Git

Скопируйте папку **`dist/next`** в `C:\Users\ivanl\Optima-Git\dist\next`. После этого из корня оригинального репозитория:

```powershell
py -3 run_local.py
```

Открыть **`http://127.0.0.1:4173/next/`**. Старый frontend по `/#offers` остаётся нетронутым. Данные V2 и Next используют разные ключи localStorage.

## Реализованные действия

- Шесть товарных предложений с самостоятельными предметными иллюстрациями, техническими характеристиками и расчётами.
- Выбор товара из реестра, фильтрация по категориям, поиск по товару, SKU и поставщику.
- Ввод количества, изменение кнопками ±, пересчёт оптовой и отдельной стоимости, доставки и экономии.
- Прогресс группового объёма и корректное сообщение о достижении/недостижении порога.
- Подтверждение и создание локальной демозаявки, статус участия, отдельный раздел заказов и отмена заявки.
- Добавление и удаление потребностей, импорт CSV/JSON и поиск подходящих групповых предложений.
- Аналитика с горизонтальными сравнениями и экспортом CSV.
- Переключение светлой/тёмной темы, мобильное действие для быстрого перехода к расчёту.

**Данные и предложения вымышлены.** Optima не подключена к банку, заказам реальных поставщиков, платежам и внешним базам данных. Порог достижения в демоданных не означает подтверждение поставщиком или оплату.

## Код

- `dist/next/index.html` — семантическая оболочка.
- `dist/next/styles.css` — новая визуальная система: крупная типографика, техническая предметная графика, адаптивная композиция.
- `dist/next/app.js` — представления страниц и пользовательские сценарии.
- `dist/next/domain.js` — **переиспользованная независимая предметная логика V2**: расчёты в целых копейках, функции формата/импорта. Не содержит визуальных компонентов.
- `dist/next/api.js` — транспорт к HTTP-бэкенду или локальному mock.
- `dist/next/mock-api.js` — **переиспользованный адаптер данных V2** с отдельным ключом хранения. Не содержит старой визуальной системы.

## Проверки

Запуск предметных тестов: `node --test tests/domain.test.mjs` (Node.js 22+). В этой среде также выполнен браузерный QA на Chromium: десктоп, мобильная ширина 390 px, расчет количества, новая и отменённая заявка, потребность, аналитика, выбор SKU, тёмная тема, проверка ошибок JS и отсутствия горизонтальной прокрутки.

Если решите подключить backend, смотрите `BACKEND-CONTRACT.md`. Сервер должен самостоятельно рассчитывать и утверждать цену, статус группы, права компании и версию условий.
