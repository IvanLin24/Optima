# Настройки компании

Экран доступен в профиле и нижней части меню. Основные пять разделов кабинета сохраняются. Форма содержит название компании, ИНН, КПП, юридический адрес, контактное лицо, телефон и почту для связи. Отдельный блок показывает почту входа и сохраняет доступ к смене режима работы и выходу.

Обязательно только название. Пустые необязательные поля сохраняются как null. ИНН проверяется по формату 10/12 цифр, КПП — 9 цифр; проверка по государственным реестрам не выполняется. Системные стартовые название и ИНН не подставляются как заполненные реквизиты в редактируемой форме. Контактная почта не заменяет логин и не меняет подтверждение аккаунта.

`GET /api/v1/company/profile` и `PUT /api/v1/company/profile` работают только с компанией авторизованного пользователя. PUT принимает profile_revision, name, inn, kpp, legal_address, contact_name, contact_phone, contact_email. Устаревшая ревизия возвращает 409 PROFILE_CONFLICT. Попытка изменить реквизиты после начала анализа или оформления заказа возвращает 409 PROFILE_LOCKED; контакты остаются редактируемыми. Старый POST /company также учитывает защиту реквизитов и увеличивает ревизию профиля.

Миграция 8c601e2a0901 добавляет nullable-поля контактов и реквизитов и profile_revision с нулевым значением для существующих записей. Существующие названия, ИНН, аккаунты, сессии и состояние закупок не удаляются. При откате приложения база не понижается; старый API совместим с добавленными колонками, но его старт должен пропускать Alembic, не знающий новой ревизии.

Проверки: API сохранения и повторного чтения, изоляция компаний, недопустимые значения, конфликт вкладок, контакты при заблокированных реквизитах и миграция существующей компании. Frontend проверяет пустые стартовые реквизиты, состав payload, защиту от запоздавшего ответа другого аккаунта, двойной submit и сохранение черновика при ошибке. Статическая форма проверена в браузере на desktop и 390 px без горизонтального переполнения.

Дополнение по запросу владельца: регистрация больше не придумывает название и ИНН. Для существующих незаполненных аккаунтов строго распознаётся прежнее системное имя с фиктивным ИНН; без истории/оформленных заказов оно очищается с CAS по profile_revision. Настоящие введённые реквизиты и реквизиты оформленных заказов не меняются. Встроенный демонстрационный каталог полностью убран из catalogOffers. Поставщик публикует предложение под названием из своих настроек. Числовое сравнение показывается только с явным источником цены, с подписью о расчётном характере; числа из legacy fixtures сами по себе не подтверждают экономию.
