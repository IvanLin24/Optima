# Optima — MVP совместных закупок

Рабочее демо: https://optima.casa/. Используется исходный дизайн Optima 0.23.0. Перед кабинетом показан экран входа и регистрации. Регистрация: email, пароль, код из письма; вход: только код. Известные одноразовые домены блокируются.

FastAPI + SQLAlchemy + PostgreSQL 17 + Alembic. Исходный интерфейс сохраняет данные через API. У каждого аккаунта своя виртуальная компания, состояние прототипа и отдельный набор данных района внутри общей БД.

Карта Тверского района Москвы: реальная административная граница, 40 вымышленных предприятий, 480 операций, 40 потребностей, 3 исторические закупки. Можно создать предприятие, потребность, тестовый платёж и совместную закупку; провести её до поставки и скачать проект соглашения. Комиссия составляет 3% положительной экономии. Все суммы, предприятия и операции демонстрационные.

Существуют API импорта выписок 1С TXT, поиска возможностей, вопросов, версий документов и демо-подтверждений. Парсинг поставщиков, банковское списание и электронная подпись не подключены. Документы требуют юридической проверки перед реальной сделкой.

## Запуск

Актуальная основа проекта — серверный релиз `20261027-v5`, перенесённый в `main`. Старый статический прототип заменён приложением с API и авторизацией.

### Скачать на Mac и открыть в Codex

```sh
git clone https://github.com/IvanLin24/Optima.git
cd Optima
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В Codex откройте всю папку `Optima`. Инструкции: `AGENTS.md` и `docs/AI_OPERATIONS.md`. API доступен на `http://127.0.0.1:8000/docs`. Для просмотра размещённого интерфейса: https://optima.casa/.

Команды выше запускают локальный API. Фронтенд использует запросы `/api/v1` с того же адреса, поэтому для полного локального сайта нужен reverse proxy: статика из `frontend/`, а `/api/` — на порт 8000. Обычный статический сервер сам API не подключает. Серверные секреты для разработки не нужны: используйте локальный `.env` по шаблону и отдельную SQLite. При `MAIL_MODE=file` письма с кодами сохраняются в `var/mail`; их нельзя публиковать.

### Windows

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Локально применяется SQLite и MAIL_MODE=file; письма с кодами находятся в var/mail. Для PostgreSQL: docker compose up --build -d после настройки .env. Почта стенда работает через Resend; секреты хранятся только на сервере.

Swagger: /docs. Все API для фронтенда: [docs/API.md](docs/API.md), [docs/openapi.json](docs/openapi.json). Сервер: [docs/HOSTING.md](docs/HOSTING.md). Проверки: [docs/VALIDATION.md](docs/VALIDATION.md).

Сборка фронта после изменения исходников: npm ci --prefix frontend, затем node frontend/build.cjs. Архив исходников: python -m scripts.package_release. Локальные БД, письма, ключи и доступы в него не включаются.

Инструкции для нейросетевого агента: [AGENTS.md](AGENTS.md), [карта проекта](docs/AI_OPERATIONS.md). Эксплуатационные настройки сервера в публичную копию не входят.

Письмо подтверждения: фирменный HTML-шаблон с текстовой версией и кнопкой открытия сайта. Код заполняется автоматически; вход требует явного подтверждения. Макет: [docs/previews/verification-email.html](docs/previews/verification-email.html).
