# Оптима — совместные закупки для бизнеса

[Рабочее демо](https://optima.casa/) · [Контракт API](docs/API.md) · [OpenAPI](docs/openapi.json)

MVP сервиса, в котором компании объединяют объёмы для оптовых условий, сохраняя отдельные заказы, реквизиты и документы. Проект команды для хакатона ВТБ. Интеграция с банковскими системами пока не подключена.

Этот репозиторий содержит полный исходный код фронтенда и бэкенда, миграции, тесты, ресурсы интерфейса и инструкции запуска. При подготовке публикации 01.11.2026 исходники приложения сверены с действующим релизом `20261030-polish-995e94` на optima.casa.

## Текущее состояние

- Регистрация: почта, пароль от 6 символов и подтверждение кодом. Вход: почта и пароль подтверждённого аккаунта.
- Один аккаунт может владеть двумя независимыми компаниями: покупателем и поставщиком. Реквизиты, контакты и состояние кабинетов разделены; второй профиль создаётся по явному выбору пользователя.
- У покупателя доступны обзор, закупки, потребности, сообщения и документы. У поставщика — заказы, товары, предложения, сообщения и документы.
- Реализованы интерфейсы публикации предложений, расчёта заказа, согласования условий, обсуждений и документов. Состояние сохраняется через API с проверкой владельца и ревизии.
- Новый кабинет пустой: название, ИНН, товары, закупки и показатели экономии не создаются за пользователя.
- Адаптивный интерфейс, светлая и тёмная темы. Общий поиск по рабочему пространству удалён; поиск внутри отдельных списков сохранён.

Реальные платежи, юридическая электронная подпись и банковская интеграция не подключены. Документы и подтверждения демонстрационные. Комиссия модели — 3% положительной экономии; сравнение требует известного источника исходной цены. Продукт ещё не предназначен для реального расчётного и юридического исполнения сделок.

В коде также сохранены API импорта выписок 1С TXT и экспериментального района с синтетическими предприятиями. Карта, аналитика и внутренние задачи не входят в основное меню текущего этапа. Эти данные не являются реальными клиентами или банковскими операциями.

## Стек и структура

FastAPI, SQLAlchemy, PostgreSQL 17, Alembic, Docker Compose. Локально доступна SQLite. Фронтенд — JavaScript-модули и CSS, сборка esbuild.

## Локальный запуск

Требуются Python 3.12+ и Node.js с npm. Docker-образ использует Python 3.14.

### macOS / Linux

```sh
git clone https://github.com/IvanLin24/Optima.git
cd Optima
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp .env.example .env
npm ci --prefix frontend
node frontend/build.cjs
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

### Windows PowerShell

```powershell
git clone https://github.com/IvanLin24/Optima.git
Set-Location Optima
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
npm ci --prefix frontend
node frontend/build.cjs
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Команды запускают API на http://127.0.0.1:8000; Swagger — http://127.0.0.1:8000/docs. Для полного локального сайта нужно обслуживать статику из `frontend/` и направлять `/api/` и `/health/` на API через reverse proxy. Открытие index.html как файла или отдельный статический сервер не подключает бэкенд. Размещённая полная версия доступна на https://optima.casa/.

В локальном `.env` по умолчанию используются SQLite и `MAIL_MODE=file`: письма подтверждения сохраняются в `var/mail`. Они приватные и не входят в исходный код. Для PostgreSQL предусмотрен `docker compose up --build -d` после настройки собственного `.env`. Не используйте доступы или секреты действующего сервера для локальной разработки.

```sh
python -m pytest -q

node frontend/build.cjs
python -m scripts.export_openapi

```
